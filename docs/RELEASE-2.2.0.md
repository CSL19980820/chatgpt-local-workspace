# Local Workspace 2.2.0

针对模型明知工作未完成却结束回复的情况，新增完成检查、未完成项回执、中断原因与可复制的续做提示。工具数从 25 增至 26。

## 行为变化

- `check_task_completion(path)` 在交付前核对该对话、该路径的计划。无计划、未完成步骤、已完成步骤缺少 `evidence`、命令仍运行或最近执行问题未通过后续计划更新记录处理结果时，返回 `can_finish: false`。
- `update_plan` 的步骤支持可选 `evidence` 字符串（最多 1000 字）；兼容不传该字段的旧调用，但没有证据的步骤不能通过完成检查。更新时保留名称相同且仍为 completed 的旧证据。
- `task_state` 为 `active`、`blocked` 或 `paused`；blocked / paused 必须填写 `reason` 和 `next_action`。paused 只应用于用户明确要求暂停。恢复时显式设置 active。普通更新保留先前的阻塞或暂停。
- 移除或重命名未完成步骤时必须填写 `explanation`；说明应反映真实范围变更，不能以删减计划冒充完成。
- 工具结果外层新增可空的 `task` 提示；正文也提醒当前对话剩余步骤与交付前检查。它们是工作流指导，不能强制模型继续调用。
- 页面始终展示待办回执与下一步，区分实际命令执行、已记录阻塞、用户暂停、待补证据、检查通过以及两分钟无调用的“待确认”。无调用可能是模型思考，不能据此宣称停止。
- “复制续做提示”只写剪贴板，由用户发回原对话；提示保留暂停/阻塞条件，并明确不新增部署、删除或对外操作授权。

## 完成检查的边界

`can_finish: true` 表示当前登记的计划、证据字段和本地执行状态满足检查条件。证据是模型填报的文本，插件无法判断其语义真实性、用户原始需求是否被完整列入计划，也不能阻止 ChatGPT 直接发送最终回复。实际验证与授权仍由宿主执行流程负责。

计划仍只保存在当前 MCP 进程中。最近工具活动最多 100 条，命令历史也有保留上限，页面展示的是有界的当前进程观测；不提供跨进程审计或自动跨轮执行。重启后需从原对话重新登记计划。

## 升级与验证

退出旧程序后启动发行包中的新版，在 ChatGPT 刷新工具并确认 `version: 2.2.0`、`tool_count: 26`。本版继续使用 OpenAI Tunnel Client v0.0.14。

验证包括真实 EXE 的待办/证据检查、运行中命令、超时与停止、失败后记录恢复、不同对话隔离、暂停/阻塞保持、范围变更保护，以及浏览器复制提示、折叠状态、窄窗口和主题呈现。另用真实两分钟空闲窗口验证待确认状态。认证 ChatGPT 的跨轮行为没有作为本地测试的成功结论。

最终 `dist` 程序运行回归报告 20 个条目通过；其中认证 Tunnel 冒烟脚本未启用，不将其退出成功计为 ChatGPT 连通证据。真实 HTTPS 附件导入、同目录官方诊断命令与既有图片/路径功能回归已执行。
